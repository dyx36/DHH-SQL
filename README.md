# DHH-SQL

This repository contains the implementation of **Dynamic Schema Linking via
Heterogeneous Hypergraphs for Text-to-SQL (DHH-SQL)**.

DHH-SQL extends the ISESL/LGESQL-style parser with:

- compound primary-key hyperedge nodes;
- foreign-key association hyperedge nodes;
- multi-hop join-path hyperedge nodes;
- top-`k` dynamic question-schema linking, with `k=2` by default;
- relation-aware RGAT encoding over question, schema, and hyperedge nodes.

## Environment

The code was tested with Python 3.10, CUDA 12.1, PyTorch 2.4.0, and DGL 2.4.0.
Install the Python dependencies and language resources before preprocessing:

```bash
python -m pip install -r requirement.txt
python - <<'PY'
import stanza
import nltk
stanza.download('en')
nltk.download('stopwords')
PY
```

If the server has no internet access, pre-download the HuggingFace model
`google/electra-large-discriminator`, the Stanza English model, and the NLTK
`stopwords` corpus into the corresponding cache directories.

## Data Layout

Download Spider from the official Spider website and place files as follows:

```text
data/
  train.json
  dev.json
  tables.json
  database/
    <db_id>/<db_id>.sqlite
```

Optional robustness splits such as Spider-SYN or Spider-DK should be converted
with the same preprocessing pipeline and passed by split name at training or
evaluation time.

## Preprocessing

`tables.bin` stores DHH-SQL hypergraph metadata, including `K_p` and `B`.
Whenever `--max_fk_path_len` or `--paths_per_table_pair` changes, regenerate
`tables.bin`, `train.bin`, `dev.bin`, and the RGAT graph binaries.

Default paper setting:

- maximum FK path length `K_p = 3`;
- retained join paths per table pair `B = 2`;
- dynamic linking top-`k = 2`.

Run:

```bash
python -u preprocess/process_dataset.py \
  --dataset_path data/train.json \
  --raw_table_path data/tables.json \
  --table_path data/tables.bin \
  --output_path data/train.bin \
  --skip_large \
  --semantic_graph \
  --max_fk_path_len 3 \
  --paths_per_table_pair 2

python -u preprocess/process_dataset.py \
  --dataset_path data/dev.json \
  --table_path data/tables.bin \
  --output_path data/dev.bin \
  --skip_large \
  --semantic_graph \
  --max_fk_path_len 3 \
  --paths_per_table_pair 2

python -u preprocess/process_graphs.py \
  --dataset_path data/train.bin \
  --table_path data/tables.bin \
  --output_path data/train.rgatsql.bin \
  --max_fk_path_len 3 \
  --paths_per_table_pair 2

python -u preprocess/process_graphs.py \
  --dataset_path data/dev.bin \
  --table_path data/tables.bin \
  --output_path data/dev.rgatsql.bin \
  --max_fk_path_len 3 \
  --paths_per_table_pair 2
```

The preprocessing code fails fast if `tables.bin` was generated by an older
version or with mismatched `K_p/B` settings.

## Training

The training script expects split names, not full file paths. For example,
`--train_path train --dev_path dev --model rgatsql` loads:

```text
data/train.rgatsql.bin
data/dev.rgatsql.bin
```

Example training command:

```bash
CUDA_VISIBLE_DEVICES=0 python scripts/text2sql.py \
  --task dhh_sql \
  --seed 999 \
  --device 0 \
  --plm google/electra-large-discriminator \
  --model rgatsql \
  --output_model without_pruning \
  --table_json data/tables.json \
  --tables_bin data/tables.bin \
  --db_dir data/database \
  --train_path train \
  --dev_path dev \
  --training \
  --optimize_graph \
  --schema_loss \
  --graph_reg_weight 1.0 \
  --dynamic_topk 2 \
  --max_fk_path_len 3 \
  --paths_per_table_pair 2 \
  --gnn_hidden_size 512 \
  --dropout 0.2 \
  --attn_drop 0.0 \
  --att_vec_size 512 \
  --score_function affine \
  --relation_share_heads \
  --subword_aggregation attentive-pooling \
  --schema_aggregation head+tail \
  --gnn_num_layers 8 \
  --num_heads 8 \
  --lstm onlstm \
  --chunk_size 8 \
  --drop_connect 0.2 \
  --lstm_hidden_size 512 \
  --lstm_num_layers 1 \
  --action_embed_size 128 \
  --field_embed_size 64 \
  --type_embed_size 64 \
  --no_context_feeding \
  --batch_size 35 \
  --grad_accumulate 5 \
  --lr 1e-4 \
  --l2 0.1 \
  --warmup_ratio 0.1 \
  --lr_schedule linear \
  --eval_after_epoch 120 \
  --smoothing 0.15 \
  --layerwise_decay 0.8 \
  --max_epoch 200 \
  --max_norm 5 \
  --beam_size 5 \
  --logdir logdir/dhh_sql
```

The full DHH-SQL path does not use precomputed lexical/value question-schema
relations as RGAT edges. Question-schema links are added dynamically at runtime
from the top-`k` positive learned similarities. `--use_static_link_fusion` is a
compatibility/ablation option and should be reported separately if enabled.

## Evaluation

Evaluate a saved checkpoint with:

```bash
CUDA_VISIBLE_DEVICES=0 python scripts/text2sql.py \
  --task dhh_sql_eval \
  --seed 999 \
  --device 0 \
  --plm google/electra-large-discriminator \
  --model rgatsql \
  --output_model without_pruning \
  --table_json data/tables.json \
  --tables_bin data/tables.bin \
  --db_dir data/database \
  --train_path train \
  --dev_path dev \
  --testing \
  --optimize_graph \
  --schema_loss \
  --dynamic_topk 2 \
  --max_fk_path_len 3 \
  --paths_per_table_pair 2 \
  --read_model_path logdir/dhh_sql \
  --logdir logdir/dhh_sql_eval
```

Checkpoints store relation-vocabulary and hypergraph-preprocessing metadata.
If relation IDs, `K_p`, or `B` differ from the current run, loading fails
instead of silently evaluating an incompatible model.

## Compatibility Notes

- Old `tables.bin`, `*.rgatsql.bin`, and checkpoints created before the DHH-SQL
  hypergraph changes are not compatible. Regenerate data and retrain.
- Training arguments `--max_fk_path_len` and `--paths_per_table_pair` are used
  to validate preprocessed artifacts. They do not alter already generated
  binaries.
- The default model uses dynamic-only question-schema edges. Static lexical or
  semantic priors are available only through explicit compatibility flags and
  should be treated as separate ablations.
